# 第3章 把产品说清楚：建立 Product Context

**核心问题：** 怎么让 AI 真正理解产品。把模糊需求变成目标、用户、场景、流程、状态和边界。

**上一章接口：** 三件套的第一块。  
**下一章接口：** Context 只回答「做什么」；「做成什么样」交给 Design System。

## 一页概念

丢给模型的如果只是「做一个 xx App」，它会补全世界的默认假设。Product Context 是**允许模型补什么、禁止补什么**的说明书。

最低完整集：一句话目标、用户与非用户、3 条关键场景、主流程、关键状态、明确不做。

## 当堂资产：模板（直接填）

```markdown
# Product Context · <产品名>

## 一句话
（谁，在什么情况下，完成什么，比现状好在哪）

## 目标
- 业务目标：
- 用户目标：
- 非目标（这次不做）：

## 用户
- 主用户：
- 次用户：
- 明确不是谁：

## 场景（至少 3 条）
| 场景名 | 触发 | 用户做什么 | 成功长什么样 | 失败怎么办 |
|---|---|---|---|---|
| | | | | |

## 主流程
1.
2.
3.

## 状态
| 对象 | 状态 | 谁能操作 | 界面必须显示 |
|---|---|---|---|
| | | | |

## 边界
- 平台 / 登录 / 数据从哪来：
- 性能或合规约束：
- Agent 不准自行发明的规则：
```

作业：把一条真实需求填进模板，分别用「只丢一句话」和「丢完整 Context」各生成一版页面清单，写下差异。

## 语料案例

1. **做产品沉淀下来的用户分析框架** · `6a252fa9000000001702aa7e`（用户场景分析）  
   可抽框架，不抄作者公司细节。
2. **用户需求分析的 6 个常用方法** · `6a8e2aff000000002400604e`  
   场景章补方法名：访谈、行为、任务、竞品等，选 1–2 个填进上表。
3. **产品实习生怎么把 PRD 写明白** · `kK的产品实战派` 目录 `ch3_产品需求文档PRD怎么写`  
   PRD 结构当「人读文档」；本课 Context 必须比 PRD 更适合模型：短、表格式、有非目标。

**不要当主案例：** 「什么是用户画像」面试标准答案、Prompt 答不上来的面经吐槽。
