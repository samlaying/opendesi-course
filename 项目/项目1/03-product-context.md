# Product Context · 健身打卡记录（代号 FitLog，名字待定）

## 一句话

自己练的人，刚练完的 30 秒内，记下今天练了什么并完成打卡，比备忘录好在：重量组数结构化、连续打卡一目了然，回看不用翻聊天记录。

## 目标

- 业务目标：跑通 Open Design 三件套的第一个真实产品（本课程的结业作品）
- 用户目标：3 次点击内完成当日打卡；随时回看「上回卧推多少公斤」和「这个月练了几次」
- 非目标（这次不做）：
  - 不做账号、云同步、多设备（第一版本地存储）
  - 不做社交、排行榜、课程内容、商城
  - 不做饮食记录、体重管理、可穿戴设备同步
  - 不做 AI 训练建议（只记录，不指导）

## 用户

- 主用户：健身房/居家自练的人，每周 2~5 练，用备忘录或脑子记重量，坚持靠自觉
- 次用户：偶尔想看看伴侣/朋友练得怎么样的旁观者（只读分享页，第一版可不做）
- 明确不是谁：教练带学员的管理需求、竞技运动员的数据分析、健身房商户的会员系统

## 场景（至少 3 条）

| 场景名 | 触发 | 用户做什么 | 成功长什么样 | 失败怎么办 |
|---|---|---|---|---|
| 练后秒记 | 刚做完最后一组，擦汗掏手机 | 选今天练的部位→选动作→填重量×组数→保存 | 30 秒内完成，看到「已打卡 · 连续 N 天」 | 网络无关（本地），最坏是重填一次，不设复杂校验 |
| 练前瞄一眼 | 到健身房，准备开始同一部位 | 打开当月视图，看上回该动作的重量 | 上回重量/组数一眼可见 | 没记过就显示「首次」，不逼先建档案 |
| 周末回看 | 周日晚 / 月初，想知道坚持得怎样 | 看月视图打卡点阵 | 本月 X 次、当前连续 Y 天、最长 Z 天 | 断卡只如实显示，不弹挽回弹窗、不发通知 |
| 忘了补记 | 第二天想起昨天没记 | 切到昨天日期补一条 | 可补记任意过去日期，streak 规则见状态表 | 补记不影响历史真实性，显示补记标记即可 |

## 主流程

1. 打开页面 → 默认停在「今天」，未打卡时主按钮就是「+ 记一笔」
2. 记一笔：部位 → 动作（可复用上次的）→ 重量×组数（多条）→ 保存即打卡
3. 保存后：今日变已打卡，streak 与月视图点阵即时更新

## 状态

| 对象 | 状态 | 谁能操作 | 界面必须显示 |
|---|---|---|---|
| 当日打卡 | 未打卡 / 已打卡 | 用户 | 顶部当前状态 + streak 天数 |
| 训练条目 | 可增删改（当日与历史均可） | 用户 | 动作名、重量、组数、是否补记 |
| 连续天数 streak | 由打卡日期计算，不可手改 | 系统 | 当前值；补记过去日期计入，未来日期不可打卡 |
| 历史记录 | 只读展示 | 用户 | 按月点阵 + 按日明细 |

## 边界

- 平台 / 登录 / 数据从哪来：纯 Web 单页，无登录；数据存 localStorage（导出 JSON 一键备份），人机同读一份文件
- 性能或合规约束：秒开、离线可用；只有用户自己的训练数据，无第三方数据源
- Agent 不准自行发明的规则：
  - 不准加账号体系、云同步、推送通知
  - 不准替用户「补打卡」或修改 streak 计算规则
  - 不准引入训练建议、评分、教练话术——记录工具只记录
  - 视觉风格归 Design System 管（见 04），Context 层不规定颜色样式
